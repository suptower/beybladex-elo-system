⚡ ELO Rating System

How Beyblade X ELO ratings are calculated — a complete guide covering all three versions of the system

🧮 The ELO Update Formula

Every version of the system uses the same underlying ELO update rule. Only the K-factor and score calculation change between versions.

Rating update
ΔR = Keff · (S − E)
ΔR — ELO change for the player
Keff — effective K-factor (controls volatility)
S — actual score for this match
E — expected score before the match
Expected score
E = 1 / (1 + 10−(RA − RB) / 400)
RA — current ELO of player A
RB — current ELO of player B

A player rated 200 ELO higher has E ≈ 0.76 — i.e. they are expected to win ~76% of the time. When both players have equal ELO, E = 0.5 for both sides.

Starting ELO
Rstart = 1000

Every new Beyblade enters the leaderboard at 1000 ELO.

🏟️ Arena Scope

ELO ratings are tracked separately per arena. Only Xtreme arena matches affect the main leaderboard and plots. Drop Attack arena results are tracked independently and do not influence Xtreme ratings.

Version 1 — Classic (Historical)

📖 Overview

Version 1 was the original ELO system: a single flat K-factor and standard binary win/loss scoring. Simple but limited — all wins were treated equally regardless of the score margin.

⚙️ K-Factor

All players used the same fixed K-factor, regardless of experience:

K = 16 (flat, for all players)

This meant a veteran Beyblade with 100 matches was just as volatile as one playing its first match — ratings were slow to converge.

🏆 Score Function

Classic binary scoring — win or lose, nothing in between:

Winner
S = 1.0
Loser
S = 0.0

A 4–3 win granted the exact same ELO gain as a 4–0 win. Match closeness was ignored entirely.

⚠️ Limitations

  • Flat K-factor gives identical volatility to new and experienced Beyblades
  • No margin of victory consideration — a 4–3 win equals a 6–0 blowout
  • Ratings converge slowly for new entrants
Version 2 — Tiered K + Dominance (Historical)

📖 Overview

Version 2 introduced two major improvements: a tiered K-factor that decreases as a Beyblade gains experience, and a dominance-based score that rewards bigger victories with higher ELO gains.

⚙️ Tiered K-Factor

K-factor now depends on match count, creating three discrete tiers:

🔰 Learning
< 6 matches
K = 40
High volatility — rating adjusts quickly in the first few matches
📈 Intermediate
6 – 14 matches
K = 24
Medium volatility — rating still moves, but more cautiously
⭐ Experienced
15+ matches
K = 12
Low volatility — stable rating, harder to gain or lose big
K-Factor definition (V2)
K = 40 if N < 6 | K = 24 if 6 ≤ N < 15 | K = 12 if N ≥ 15

Problem: the jump from K=24 to K=12 at match 15 creates a sudden cliff in volatility.

🏆 Dominance-Based Score (V2)

Instead of a flat win/loss, the score scales with the point differential:

Winner score
Swinner = BASE_WIN + (1 − BASE_WIN) × dominance + overkill_bonus
BASE_WIN = 0.75 (minimum reward for any win)
dominance = min(diff / 4, 1.0)
diff = winner score − loser score
overkill_bonus = up to 0.25 for wins beyond 4–0
Loser score
Sloser = 1 − Swinner

⚠️ Limitations

  • Discrete K-factor jumps create sudden volatility cliffs at match 6 and match 15
  • No form/momentum component — a Beyblade on a losing streak gets the same K as one on a winning streak
✅ Version 3 — Current System

📖 Overview

Version 3 is the current system. It replaces both discrete K-tiers and the dominance formula with fully smooth, differentiable functions. Three complementary mechanisms work together to produce accurate, stable, and responsive ratings:

📉
Smooth K-base
Exponential decay from K=32 (new) to K=16 (veteran)
📈
EMA Form Multiplier
Recent performance amplifies K for streaks and slumps
〰️
tanh Margin Score
Smooth, zero-sum scoring based on point differential

⚙️ 1 — Smooth K-base (Exponential Decay)

Instead of discrete tiers, K-base decreases continuously as matches are played:

K-base formula
Kbase(N) = Kmin + (Kmax − Kmin) · e−N / τ
Kmin = 16 (floor for veterans)
Kmax = 32 (ceiling for new entrants)
τ = 15 (decay constant, in matches)
N = number of matches played so far
N = 0 → K = 32.0
N = 5 → K ≈ 27.0
N = 15 → K ≈ 21.9
N = 30 → K ≈ 18.0
N = 60 → K ≈ 16.2
N → ∞ → K → 16.0

No cliffs — the transition is completely smooth. A Beyblade at match 14 and one at match 15 have nearly identical K-factors.

📈 2 — EMA Form Multiplier

The effective K-factor is boosted when a Beyblade is performing better or worse than its ELO predicts. This allows faster correction when a rating drifts too far from a Beyblade's true strength.

Form EMA update (after each match)
form_emanew = α · δ + (1 − α) · form_emaold
δ = S − E (actual minus expected score this match)
α = 2 / (10 + 1) ≈ 0.182 (smoothing factor)
First match: form_ema is seeded with the first δ value
Effective K-factor
Keff = Kbase · (1 + αform · |form_ema|)
αform = 2.5 (form amplification factor)
💡
What this means: A Beyblade that has been winning much more than expected (positive form_ema) gets a higher K_eff — meaning its rating rises faster toward its "true" level. The same applies in the opposite direction for underperformers. Older matches decay geometrically rather than being dropped abruptly, so the EMA responds smoothly to momentum shifts.

〰️ 3 — tanh Margin Score (Zero-Sum)

The score function is built around the tanh (hyperbolic tangent), a smooth S-curve that saturates for extreme results:

Winner score
Swinner = 1 + a · tanh( b · (m − T) / T )
m = point difference (winner score − loser score)
T = target points (4 for Race-to-4, 7 for finals)
a = 0.18 (amplitude)
b = 2.2 (steepness)
Loser score (zero-sum)
Sloser = 1 − Swinner

Reference 4–0 is the calibration anchor: S = 1.000 exactly.
Close loss 3–4 gives Sloser ≈ 0.167, not 0 — a narrow defeat is penalised less than a blowout.
Overshoot Winning beyond 4–0 is rewarded — overshoots push S > 1 and correspondingly push the loser to S < 0.
Zero-sum Swinner + Sloser = 1 always, so ΔRA + ΔRB = 0 when K-factors are equal.

🔄 Match Sequence Summary

  1. Look up pre-match ELOs: RA and RB
  2. Compute expected scores: EA = 1 / (1 + 10−(RA−RB)/400)
  3. Read current form_ema for each Beyblade (or None for the first match)
  4. Compute Kbase(N) from match count N (Xtreme arena only)
  5. Compute Keff = Kbase · (1 + 2.5 · |form_ema|)
  6. Compute actual scores SA, SB via tanh formula
  7. Apply update: RA += round(Keff,A · (SA − EA))
  8. Update form_ema: form_ema += 0.182 · (δ − form_ema)

✅

⚡

What do these metrics mean?
Prediction Accuracy
The proportion of non-drawn matches in which the player with the higher pre-match ELO (E > 0.5) went on to win. Matches where both players had exactly the same ELO are excluded.
Brier Score
Mean squared error between the predicted win probability (E) and the actual binary outcome (1 = win, 0 = loss). A perfectly calibrated, omniscient model scores 0; a model that always predicts 50 % scores 0.25 (the uninformed baseline).
BS = mean( (E − outcome)² )
Brier Skill Score
Relative improvement of the Brier Score over the uninformed baseline (always-0.5 model). A positive value means the ELO model does better than random guessing.
BSS = 1 − BS / 0.25
Log Loss
Mean cross-entropy between the predicted probability and the actual outcome. It penalises overconfident wrong predictions heavily. The uninformed baseline (always 50 %) scores ln(2) ≈ 0.693.
LL = −mean( outcome·log(E) + (1−outcome)·log(1−E) )
Margin RMSE
Root mean squared error between the predicted win probability (E) and the actual margin-based score (S) used for ELO updates. Unlike Brier Score, this captures how well E predicts the magnitude of the result — a dominant 6–0 win gives S > 1 while a 3–4 near-miss gives S ≈ 0.17, so a higher Margin RMSE indicates the probability is not well aligned with the actual result margins.
MarginRMSE = sqrt( mean( (E − S)² ) )
📈 How to further improve the system
More match data (highest impact)
With ~376 Xtreme arena matches the dataset is relatively small. ELO systems typically need thousands of matches to reach reliable calibration. High-probability buckets (70–80 %) have very few matches, leading to noisy calibration that will self-correct as more high-skill-gap matches accumulate.
Tune the ELO scale D (currently 400)
The expected score formula uses E = 1 / (1 + 10−(Δr/D)). A smaller D (e.g., 300) spreads ratings faster and makes E more decisive; a larger D (e.g., 500) compresses predictions toward 0.5. Reducing D slightly would push well-matched Beys toward more confident predictions, potentially improving accuracy.
K-factor parameter tuning (K_max, K_min, τ)
Increasing τ (currently 20) slows the decay from K_max to K_min, keeping ratings more volatile for longer and allowing faster convergence. Reducing K_max (currently 40) would compress the rating spread, correcting the overconfidence seen in high-probability buckets.
Match-type stratification
Exhibition, regular-season, and tournament finals are currently treated identically. Weighting finals or playoff matches more heavily (higher K) could improve the signal-to-noise ratio.
Head-to-head recency bonus
A small ELO adjustment based on recent head-to-head record between two specific Beys could improve short-term accuracy, though it risks over-fitting on small pair samples.
Note on binary vs continuous outcomes
Accuracy, Brier Score, and Log Loss all use the binary outcome (win = 1, loss = 0) as ground truth. This is the correct convention for probability-calibration metrics because E is a win probability, not a margin predictor. The continuous margin score S is only used for ELO updates — it intentionally exceeds [0, 1] for dominant results (e.g., S ≈ 1.09 for a 5–0 win). The separate Margin RMSE metric quantifies how well E tracks S as a whole.
